# Медицинская информационная система для поликлиники

## Проблема
Сейчас очереди очень странно работают. То есть у врача есть несколько очередей: запись через сервисы, от других врачей (ну то есть пришел к терапевту, нужно записать к лору), от себя. Сделано, чтобы нельзя было условно говоря забить чем то одним. 

Минусы — нельзя записывать в удобное время. Ну то есть очередь фиксирована по времени. Типо для пациента — с xx до yy, для других врачей — с zz до hh и т.д. 

Также отсутствует какая-то сводка по эпизобу болезни, то есть надо лазить по карте пациента и смотреть, куда он ходил до этого, к какому врачу, что этот врач писал.

## Наша ИС
Будет единая система записи, где не будет такого жесткого разделения очередей. Система сможет учитывать, откуда идет запись, насколько срочно нужно принять пациента и какое время ему удобно, и уже на основе этого предлагать свободные окна. 

Также будет сводка по текущему эпизоду болезни. То есть врач сможет сразу посмотреть основную информацию: с чем пациент пришел, у каких врачей уже был, что ему назначали, какие обследования он проходил и что нужно делать дальше. 

Еще врач сможет направлять пациента к другому специалисту, и это будет не просто отдельное направление, а какая-то цепочка ведения пациента. Например, терапевт направил на анализы, потом к кардиологу, потом снова на повторный прием. Система будет показывать, какие этапы уже пройдены, а какие еще нет. 

Для пациента будет возможность записаться на прием, выбрать удобное время и заранее описать свои жалобы. По этим жалобам система сможет примерно определить, к какому специалисту лучше обратиться и насколько срочно нужен прием. А также врач уже будет получать какую-то информацию о том, что с пациентом, чтобы не с нуля его расспрашивать и тем самым экономить время приема. 

Если свободных мест нет, можно сделать лист ожидания. То есть если кто-то отменил запись, система сможет предложить освободившееся место другому пациенту. Также можно добавить уведомления о приеме и о том, что нужно пройти следующий этап лечения.
