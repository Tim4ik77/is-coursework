Вопросы для согласования:

1. Резерв реализован внутренним состоянием `held` записи и отдельной сущностью предложения `slot_holds`. Это обеспечивает общие ограничения занятости для резервов и приёмов.
2. На один день врача назначается одна специальность. Врач может иметь несколько специальностей в разные дни (связь M:N).
3. Три квоты в сумме равны числу слотов; время освобождения общее для рабочего дня. После него ограничения типов снимаются, основания записи сохраняются.
4. Истекшая заявка получает статус `expired`; для повторного участия пациент создает новую заявку. Следующий кандидат получает предложение при следующем вызове `offer_slot`.
5. Изменение рабочего дня с историей приёмов запрещено целиком. Это более строгое правило, чем запрет изменения только занятых интервалов.
6. Базовый опросник содержит текстовые вопросы; изменение использованной версии требует новой версии.
7. Сервер приложения выполняет авторизацию и проверку доступа к конкретному пациенту. В этом этапе реализована целостность БД, а не сервер авторизации.

SQL-реализация подготовлена до получения согласования как проверяемый проект. При замечаниях преподавателя модель и SQL должны быть изменены совместно.
